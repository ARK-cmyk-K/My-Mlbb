# Task 02-02 — Protected Dashboard Shell and Sidebar

Inspect current routing, auth implementation, design tokens, and state files first.

Build the private dashboard layout with a collapsible modular sidebar, contextual workspace header, responsive behavior, clear active navigation, keyboard accessibility, and visible draft/published/unsaved status slots. Use the approved professional admin-console visual direction and shared tokens. Protect the route server-side using the established authorization helper.

Create only the shell and navigation placeholders needed for later features; do not implement collection CRUD, publishing, or appearance editing here. Avoid fake status indicators that imply backend operations succeeded.

Acceptance criteria: unauthorized requests are rejected server-side, layout is usable on mobile and desktop, accessibility basics are covered, and checks/state are updated.
